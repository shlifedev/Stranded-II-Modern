# 기능 아이디어와 우선순위

[English](feature-ideas.md) · [한국어](feature-ideas-ko.md)

[README로 돌아가기](../../README-ko.md) · [개발 가이드](../development-ko.md) · [QOL 설정](../qol-ko.md) · [Extended 개발 구상](../extended/plan-ko.md)

구현됐거나 확정된 기능 목록이 아닌 제안 문서입니다. 아이디어마다 근거가 되는 현재 소스(`main`의 `3a9dfc7`)를 함께 적었습니다. 이 문서를 위해 빌드나 실행은 하지 않았으며, 아이디어별로 필요한 검증을 따로 적었습니다.

## 읽는 법

| 항목 | 의미 |
| --- | --- |
| 공수 | 개발자 1명이 검증까지 마치는 기준으로 **S** 약 1주 이하 · **M** 1–3주 · **L** 한 달 이상 |
| 우선순위 | **P1** 다음 분기 추천 · **P2** 다음 후보 · **P3** 백로그 |
| 에디션 | 표시·입력·데이터 보호·도구 아이디어는 공유합니다. 플레이 경험을 바꾸는 것은 선택 옵션으로 두고 기본판 기본값은 원작 동작을 유지합니다. 규칙·콘텐츠 변경은 Extended 전용입니다. |

## 다시 제안하지 않는 기능

아래 기능은 이미 있습니다. 이 문서의 아이디어는 이를 반복하지 않고 그 위에 쌓습니다.

- 다섯 가지 QOL(조합법 도감, 보관함 빠른 이동, 빈 시체 자동 닫기, 자동 정렬, 건축 연속 입력)과 F2 FPS 표시 — [QOL 설정](../qol-ko.md)
- 치트·설정 미리 적용·로그·CPU/GPU 프로파일러·성능 테스트 장면을 갖춘 개발자 메뉴, 네이티브·웹 벤치마크 — [개발 가이드](../development-ko.md)
- Stranded II Studio(3D 편집, 스크립트, 템플릿, 검증, 내보내기) — [Studio](../studio-ko.md)
- 웹(WebGPU)·Apple Silicon macOS 빌드, EN/KO/DE 기본 포함과 사용자 언어·글꼴 추가를 지원하는 언어팩
- 그래픽 향상(수면, 조명, 그림자, 대기, FXAA/MSAA), FPS 제한 해제, 테두리 없는 창·창 모드
- 빠른 저장·불러오기 수정, 다섯 칸 순환 자동 저장, 이어하기, `.bak` 세이브 백업
- HUD 없이 찍히는 F1 스크린샷

개발자 백로그에 이미 있는 아이디어는 [기존 백로그](#기존-백로그)에 구현 메모만 적었습니다.

## 1. 플레이어 데이터 보호

### 1.1 웹 세이브 내보내기·가져오기와 영구 저장소

- **내용:** 웹 페이지에 **세이브 내보내기**와 **세이브 가져오기** 버튼을 추가합니다. 내보내기는 `/persist/classic/saves`와 영구 저장된 설정을 비압축 ZIP 하나로 묶고, 가져오기는 이를 복원한 뒤 페이지를 다시 불러옵니다. 저장소 준비가 끝나면 `navigator.storage.persist()`를 한 번 요청합니다.
- **이유:** 웹 세이브는 한 브라우저 프로필의 한 주소에 속한 IndexedDB에만 있습니다. 사이트 데이터를 지우면 함께 삭제되고 다른 브라우저, 로컬 개발 주소, Windows나 macOS로 옮길 수 없습니다([웹 구현 원리](../web-architecture-ko.md)). `src/web/shell.js`에는 내보내기 경로가 없고 영구 저장소도 요청하지 않습니다.
- **위치:** `src/web/shell.js`(`prepareStorage`, 순차 실행되는 `sync()` 큐, Web Locks 보호)와 `src/web/index.html`. 가져오기는 각 `.sav`를 `modern_save_valid`(`src/engine/includes/modern_saves.bb`)와 같은 헤더·끝 표식 사전 검사로 확인하고, 임시 이름에 쓴 뒤 교체되는 파일을 `.bak`으로 남기며, `FS.syncfs`가 끝난 뒤에만 성공을 알립니다.
- **에디션:** 웹이 지원하는 유일한 에디션인 기본판.
- **공수 / 리스크:** S–M, 리스크 낮음. 파일 크기를 제한하고 알 수 없는 경로를 거부하며, 더 최신 세이브를 교체하기 전에 확인을 받습니다. 처음에는 웹 간 이동만 지원하고, 데스크톱 세이브 가져오기는 별도의 바이너리 호환성 확인이 필요합니다.
- **검증:** `check --platform web`의 저장소 트랜잭션 검사를 확장하고, Chrome·Edge에서 내보내기 → 사이트 데이터 삭제 → 가져오기 → 불러오기를 확인합니다.
- **우선순위:** P1

### 1.2 Windows ZIP의 안전한 업데이트

- **내용:** (a) 기본값을 `core/modern.default.ini`, `sys/controls.default.cfg`처럼 별도 이름으로 배포하고 플레이어 파일이 없을 때만 이를 바탕으로 만듭니다. 그러면 새 릴리스를 기존 폴더에 덮어 풀어도 플레이어의 선택이 유지됩니다. (b) 이전 설치 폴더에서 세이브, 키 설정, `sys/settings.cfg`, 알려진 `core/modern.ini` 키를 복사하는 **다른 폴더에서 가져오기**를 추가합니다. (c) **세이브 폴더 열기**를 추가합니다.
- **이유:** Windows 세이브와 설정은 압축을 푼 폴더 안에 있습니다. 패키징은 세이브, `settings.cfg`, 실행 폴더의 `modern.ini`를 제외하지만 저장소 기본 `core/modern.ini`와 공식 `sys/controls.cfg`·`sys/scriptcontrols.cfg`는 포함합니다(`src/devtools/ci.py`의 `player_data`·`release_members`, `config/game-files.json`). 따라서 기존 폴더에 덮어 풀면 FPS, 화면, 언어, QOL, 그래픽 향상과 키 설정이 초기화되고, 새 폴더에 풀면 세이브 없이 시작합니다. macOS 앱은 이미 Application Support에 데이터를 보관합니다.
- **위치:** 기본값 계층은 `src/devtools/ci.py`, `modern_config`(`modern_runtime.bb`), `load_settings`(`load_settings.bb`). 폴더 선택과 탐색기 열기는 `platform.windows` 서비스, 임시 파일을 거친 복사는 `modern_files.bb`의 `modern_file_copy`·`modern_commit_file`, 메뉴는 `menu.bb`의 설정 화면.
- **에디션:** 공유. Windows 먼저.
- **공수 / 리스크:** (a) S, (b)·(c) M. 지금은 `controls.cfg`가 없으면 모든 키 설정이 0으로 남으므로 기본값 계층은 항상 유효한 파일을 만들어야 합니다. `mod_setup`(`mods.bb`)도 새 모드에 `sys/controls.cfg`를 복사하므로 같은 대체 경로가 필요합니다. 기존 세이브는 백업 없이 덮어쓰지 않습니다.
- **검증:** 두 버전을 패키징해 두 번째를 첫 번째 위에 덮어 풀거나 새 폴더에 푼 뒤 게임에서 설정·키 설정·세이브를 확인하고, 두 에디션의 `check`를 실행합니다.
- **우선순위:** P1

### 1.3 선택형 시간 기반 자동 저장

- **내용:** 기존 자동 저장 큐와 다섯 칸 순환 슬롯을 이용해 플레이 시간 10·20·30분마다 자동 저장하는 설정입니다.
- **이유:** 엔진은 스크립트가 `autosave`를 호출할 때만 자동 저장합니다. `parser_commands.bb`가 모드 3을 큐에 넣고 `modern_process_saves`가 `AUTOSAVE*.sav`를 순환합니다. 스크립트가 이를 호출하지 않는 맵은 수동 저장에 의존하므로 크래시가 나면 마지막 저장 이후 진행을 모두 잃습니다. 어떤 공식 맵이 `autosave`를 호출하는지는 준비된 리소스로 따로 확인해야 합니다.
- **위치:** 게임 루프의 게임 시간 기반 타이머(`modern_runtime.bb`). `game_m_loadsave=1`이고 메뉴나 시퀀스가 없으며 플레이어가 살아 있을 때만 `modern_queue_save(3)`으로 큐에 넣습니다. `qol.bb`의 QOL 배열은 다섯 칸으로 고정돼 있으므로 옵션을 추가하려면 배열, 설정 → QOL 배치, `verify_qol_logic.py`를 함께 늘려야 합니다.
- **에디션:** 공유. 기본판 기본값 OFF, Extended는 QOL 기본값 정책을 따릅니다.
- **공수 / 리스크:** S–M. 큰 맵은 저장 중 끊김이 생길 수 있으며 스크립트 시퀀스 중에는 저장하지 않습니다.
- **검증:** 두 에디션의 `verify_qol_logic.py`·`verify_game.py`, 게임에서 순환과 이어하기가 가장 최신 슬롯을 고르는지 확인합니다.
- **우선순위:** P1

## 2. 진단

### 2.1 로컬 오류 보고서와 크래시 기록

- **내용:** Blitz 런타임 오류나 네이티브 크래시로 게임이 멈추면 버전·빌드 정보, 에디션, 플랫폼, GPU 어댑터, 현재 설정과 최근 로그를 `core/reports/<time>.txt`에 씁니다. 다음 실행 때 메인 메뉴에서 폴더를 열거나 GitHub 이슈용 요약을 복사할 수 있게 합니다. 자동 업로드는 하지 않습니다.
- **이유:** Windows에서 `stub.windows.cpp`는 디버거 없이 게임을 실행합니다. 이때 `_bbDebugError`(`blitz/debug.cpp`)는 `bbRuntimeLog`까지만 전달되어 stdout/stderr와 메모리 안의 개발자 메뉴 로그에만 기록되고, 프로세스는 코드 1로 종료됩니다. 이 경로는 파일을 쓰거나 대화상자를 띄우지 않으며, stub은 예외 처리기도 설치하지 않습니다. 개발자 메뉴 로그는 2,048건을 보관하지만(`debugui.cpp`) 프로세스와 함께 사라지고, `diagnostics=1`은 타이밍과 이동만 기록합니다.
- **위치:** `src/blitz3d/src/modules/bb/stub/stub.windows.cpp`(Blitz 오류, `SetUnhandledExceptionFilter`, 선택적 `MiniDumpWriteDump`), `stub.posix.cpp`(macOS, 기존 `BB_BACKTRACE` 덤프 활용), `stub.web.cpp`와 `src/web/shell.js`(페이지에서 보고서 표시·복사). 보고서는 `debugui/debugui.cpp`의 로그 링 버퍼를 읽습니다. 어댑터 정보는 `graphics.webgpu.cpp`에 아직 어디서도 호출하지 않는 `wgpuAdapterGetInfo` 조회가 필요합니다. 다음 실행 알림은 `menu.bb`에 둡니다.
- **에디션:** 공유, 모든 플랫폼.
- **공수 / 리스크:** M. 메모리가 손상된 뒤에도 처리기가 동작해야 하므로 버퍼를 미리 할당하고 크래시 경로에서 할당하지 않습니다. 경로의 사용자 이름은 지웁니다. 세이브는 건드리지 않습니다.
- **검증:** Windows·macOS의 별도 런타임 복사본에서 테스트 전용 `RuntimeError`와 강제 접근 위반을 일으켜 보고서 내용과 다음 실행 알림을 확인합니다.
- **우선순위:** P1

## 3. 캡처와 공유

### 3.1 스크린샷 개선과 사진 모드

- **내용:** 1단계는 `screenshots/` 아래에 시각이 들어간 이름의 PNG로 저장하고, 웹 빌드에서는 파일을 내려받게 하며, HUD를 포함하는 선택형 캡처를 추가합니다. 2단계는 게임을 일시정지하고 HUD를 숨긴 채 FOV·시간대 조절과 제한된 자유 카메라를 제공하는 사진 모드입니다.
- **이유:** F1(`game.bb`)은 `RenderWorld` 직후 `screenshot()`(`functions.bb`)을 호출하므로 이미 HUD 없는 화면을 찍습니다. 하지만 `saveCanvas`(`graphics/graphics.cpp`)는 비압축 24비트 BMP를 모드 폴더에 쓰며 2048×1152에서 약 7MB입니다. 웹 빌드에서는 이 폴더가 `/persist` 밖의 메모리 파일 시스템에 있어 파일을 꺼낼 수 없습니다.
- **위치:** `graphics.cpp`(기존 `stb_image.h` 옆의 `stb_image_write` 등 PNG 인코더), `functions.bb`, `src/web/shell.js`(Blob 다운로드). `ci.py`의 `player_data`는 이미 `screen_*`을 제외하므로 새 폴더도 추가합니다. 사진 모드는 개발자 메뉴의 일시정지·위치 도구를 재사용할 수 있습니다.
- **에디션:** 공유. 사진 모드는 일시정지만 하며 게임 상태를 바꾸지 않습니다.
- **공수 / 리스크:** 1단계 S, 2단계 M. 읽어오기 때문에 한 프레임이 멈추지만 캡처에는 허용할 만합니다.
- **검증:** Windows·macOS·웹에서 HUD 포함·미포함 캡처, 패키지가 해당 폴더를 계속 제외하는지 확인합니다.
- **우선순위:** 1단계 P1, 2단계 P2

## 4. 화면과 접근성

### 4.1 큰 화면용 UI 배율

- **내용:** 2D UI와 HUD를 3D 렌더 해상도와 독립적으로 배율을 적용하는 가상 캔버스에 그립니다.
- **이유:** 창은 원작 800×600 배치용 고정 좌표에 그려집니다(`interface.bb`·`menu.bb`의 `DrawImage gfx_win,215,0`). 1920×1080으로 렌더하면 메뉴가 왼쪽 위 구석만 차지하고 글자가 작습니다. 지금은 렌더 해상도를 낮추는 것 외에 방법이 없고, 그러면 3D 장면도 흐려집니다.
- **위치:** `graphics.webgpu`의 2D 캔버스와 화면 출력, 테두리 없는 창 배율에 쓰는 기존 마우스 좌표 변환, 옵션은 `modern_settings.bb`. 800×600 창을 가운데 정렬하는 것은 더 작은 배치 작업이며 UX 작업 범위입니다.
- **에디션:** 공유. 기본값 100%.
- **공수 / 리스크:** L, 리스크 높음. 백버퍼 `CopyRect`(수면·스크립트 효과), 스크린샷, 3D 패스 사이에 그리는 2D, 정수가 아닌 배율에서의 비트맵 글꼴 선명도를 모두 다뤄야 합니다.
- **검증:** `verify_engine.py --render` 픽셀 검사 후, 여러 배율·DPI에서 게임의 메뉴, 인벤토리, 일기, QOL 검색 EDIT 위치와 IME를 확인합니다.
- **우선순위:** P2

### 4.2 시야각(FOV) 설정

- **내용:** 기본값이 현재 시야와 같은 FOV 슬라이더입니다.
- **이유:** `src/engine`은 `CameraZoom`을 호출하지 않으므로 모든 화면이 Blitz 기본 줌 1.0을 씁니다. 멀미에 민감한 플레이어와 울트라와이드 사용자는 다른 FOV가 필요한 경우가 많습니다.
- **위치:** 메인 카메라 `cam`(`load_setup.bb`), 수면 반사 카메라 `env_watercam`(`e_environment.bb`), `render_*` 옵션(`remaster.bb`)처럼 다루는 `modern.ini` 키.
- **에디션:** 공유. 기본값은 바꾸지 않습니다.
- **공수 / 리스크:** S. 컬링이 `EntityInView`(`cull.bb`)를 쓰므로 시야가 넓어지면 더 많은 오브젝트를 그리고, 손에 든 무기 위치 조정이 필요할 수 있으며, 반사 카메라도 같은 줌을 써야 합니다.
- **검증:** `verify_engine.py --render`, 게임에서 양 끝 값의 무기·수면 반사·성능을 확인합니다.
- **우선순위:** P2

### 4.3 가독성과 색상 옵션

- **내용:** 빨강·초록 메시지 스타일의 대체 색상, 그리고 상태·스크립트가 거는 흐림(어지러움, 취함, 사망)을 약하게 하는 "화면 효과 줄이기" 옵션입니다.
- **이유:** 실패·성공 메시지는 빨강(`Cbmpf_red`)·초록(`Cbmpf_green`) 글꼴 스타일에 의존합니다. `fonts.py`는 언어마다 일곱 가지 스타일 페이지를 만들 때 원작 `font_norm_bad.bmp`·`font_norm_good.bmp`에서 글자색을 가져옵니다. 지속적인 모션 블러는 제거했지만 상태와 스크립트는 여전히 `mb_override`(`handle_states.bb`, `motionblur.bb`)로 흐림을 겁니다.
- **자막:** 전체 자막 시스템은 필요 없습니다. 플레이어 음성(`speech.bb`의 `speech()`)은 짧은 반응이며 대부분 이미 화면 메시지와 함께 나옵니다(예: `nospace`, `buildingsite`). `handle_items.bb`의 일부 `negative` 반응은 소리뿐이고 맵 스크립트의 `speech` 호출(`parser_commands.bb`)도 그럴 수 있으므로, 여기에 짧은 자막을 붙이면 충분합니다.
- **위치:** `src/devtools/fonts.py`(추가 스타일 페이지), `load_bmpf.bb`(스타일 선택), `motionblur.bb`의 `mb_update` 흐림 상한, 자막은 `speech.bb`, 설정 메뉴.
- **에디션:** 공유. 기본값은 원작 그대로.
- **공수 / 리스크:** M. 페이지가 늘면 언어팩이 커지므로 모든 언어의 미리보기를 확인합니다.
- **검증:** 두 에디션의 `localize`·`check`, 게임에서 옵션을 켜고 끈 상태의 메시지와 효과를 비교합니다.
- **우선순위:** P3

## 5. 입력

### 5.1 게임패드 지원

- **내용:** 1단계는 SDL 게임 컨트롤러를 핫플러그와 함께 열고, 스틱·버튼을 기존 동작(이동 키, 마우스 시점, 공격·사용, 단축 슬롯, 메뉴·Esc)에 데드존과 프레임 시간 보정을 적용해 연결합니다. 2단계는 인벤토리·제작·메뉴용 가상 커서와 버튼 안내를 추가합니다. EXE를 비 Steam 게임으로 추가하는 Steam Deck 플레이어를 위한 커뮤니티 Steam Input 배치는 문서로 먼저 제공할 수 있습니다.
- **이유:** Windows·macOS·웹이 공유하는 `runtime.sdl`은 `afterCreate`에서 원시 `SDL_Joystick` 장치를 한 번만 열고, 게임 컨트롤러 매핑이나 핫플러그 처리가 없습니다. 게임은 로고 건너뛰기에만 조이스틱을 씁니다(`unrealsoftware.bb`의 `GetJoy`).
- **위치:** `src/blitz3d/src/modules/bb/runtime.sdl/runtime.sdl.cpp`, `input/commands.decls`(새 컨트롤러 조회 명령), `input.bb`·`game_input.bb`(`in_keys` 기준 동작 매핑).
- **에디션:** 공유. 컨트롤러를 쓰기 전에는 동작하지 않습니다.
- **공수 / 리스크:** L, 1단계만은 M. UI가 마우스 중심(드래그 앤 드롭, 조합법 검색 EDIT, 맵 에디터)이므로 에디터는 마우스 전용으로 둡니다.
- **검증:** `verify_engine.py --input`에 컨트롤러 이벤트 시뮬레이션을 추가하고, Windows·macOS 게임에서 Xbox·PlayStation 컨트롤러를, 웹에서는 브라우저 Gamepad API를 확인합니다.
- **우선순위:** P2

## 6. 모드와 Studio

### 6.1 게임 내 모드 선택

- **내용:** `mods/` 아래에서 `sys/game.inf`가 있는 폴더를 나열하고, 설정에서 고른 모드를 `core/modern.ini`의 `mod=`로 저장한 뒤 언어 설정처럼 재시작 후 적용합니다.
- **이유:** 모드는 `-mod <name>` 명령줄 인수로만 고를 수 있습니다(`load_commandline.bb`). `mods.bb`는 이미 새 모드 폴더를 구성하고 `core/mods.inf`에 기록하며, 세이브와 `sys/*.cfg`도 모드별로 나뉘어 있습니다.
- **위치:** `load_commandline.bb`(`ChangeDir` 전에 저장된 선택 읽기), `mods.bb`, 설정 메뉴. macOS는 Application Support 프로필 옆에 사용자 모드 위치를 정해야 하며, 웹 빌드는 범위 밖입니다.
- **에디션:** 공유.
- **공수 / 리스크:** M. 언어팩은 기본 게임 텍스트를 매핑하므로 모드 전용 텍스트는 모드 자체 문자열로 표시됩니다. 모드가 깨져도 지금 `parse_commandline`처럼 기본 게임으로 돌아올 수 있어야 합니다.
- **검증:** 정상 모드, 없는 모드, 깨진 모드로 선택·재시작·복귀를 해 보고 세이브와 설정이 분리되는지 확인합니다.
- **우선순위:** P2

### 6.2 Studio 결과를 설치형 모드 패키지로 내보내기

- **내용:** 변경된 파일과 매니페스트(대상 에디션, 기준 해시, 번역)만 쓰는 Studio 내보내기 대상과, 이를 기본 모드 폴더의 복사본에 적용하는 게임 또는 런처 단계를 추가합니다.
- **이유:** 지금 Studio 내보내기(`overrides/`, `locales/`, `manifest.json`)는 `resources/editions/extended/`에 병합해 저장소에서 빌드하는 용도라([Studio](../studio-ko.md)) 플레이어는 개발 환경 없이 콘텐츠를 해 볼 수 없습니다. 변경된 파일만 배포하면 원작 게임 에셋을 재배포하지 않아도 됩니다.
- **위치:** `src/devtools/studio_core`의 내보내기, `mods.bb`의 모드 구성. 6.1에 의존합니다.
- **에디션:** 콘텐츠는 Extended 기준으로 작성하므로 대상 에디션을 기록하고 다르면 경고합니다.
- **공수 / 리스크:** M. 패키지 충돌과 기준 버전 불일치는 명시적인 오류로 알려야 합니다.
- **검증:** 토닉 예제를 내보내 릴리스 폴더 복사본에 설치하고 플레이한 뒤 제거합니다.
- **우선순위:** P3

### 6.3 무작위 섬 시드

- **내용:** 무작위 섬을 만든 뒤 시드를 보여 주고, 시드를 입력해 같은 섬을 다시 만들 수 있게 합니다.
- **이유:** `load_setup.bb`는 `SeedRnd(MilliSecs())`로 난수를 한 번만 초기화합니다. 무작위 섬 메뉴(`menu.bb`, `randommap.bb`)는 크기·지형·프로필을 고르지만 시드는 없습니다. 시드가 있으면 섬을 공유하고 버그 보고를 재현할 수 있으며, 벤치마크는 이미 시드 기반 생성을 씁니다(`dev_benchmark.bb`).
- **위치:** `randommap.bb`의 `randommapcreate()`·`load_randommap()`과 무작위 섬 메뉴. 생성할 때만 시드를 적용하고 이후에는 시계로 다시 초기화해 게임 중 난수는 예측할 수 없게 둡니다.
- **에디션:** 공유. 규칙은 바꾸지 않습니다.
- **공수 / 리스크:** S–M. 생성 과정이 난수를 고정된 순서로 소비해야 하며, x64·ARM64·wasm 간 부동소수점 차이로 같은 시드에서 다른 섬이 나올 수 있습니다.
- **검증:** 플랫폼마다 같은 시드로 반복 생성한 맵의 해시를 비교합니다.
- **우선순위:** P2

## 7. 설정과 업데이트

### 7.1 그래픽 프리셋과 첫 실행 추천

- **내용:** 기존 `sys/settings.cfg` 항목과 `render_*` 키를 설정하는 낮음/중간/높음/최고 프리셋, 그리고 첫 실행(`settings.cfg` 없음) 때 메뉴 장면을 짧게 측정해 프리셋을 추천합니다.
- **이유:** 새 설치는 최고 품질로 시작합니다(`load_settings.bb`: 시야 거리 4, 수면 6, 풀 4 등). 빠른 데스크톱에는 맞지만 내장 GPU와 브라우저에서는 느리게 시작할 수 있고, 한 번에 낮출 곳이 없습니다.
- **위치:** `menu.bb`·`remaster.bb`의 그래픽 설정. 측정은 `dev_benchmark.bb`의 성능 테스트 코드를 재사용할 수 있습니다. `graphics.webgpu.cpp`의 WebGPU 어댑터 요청은 아직 Blitz에 어댑터 정보를 제공하지 않습니다.
- **에디션:** 공유. 플레이어가 프리셋을 고르거나 추천을 수락할 때만 적용하며, 저장된 설정을 몰래 바꾸지 않습니다.
- **공수 / 리스크:** M. 짧은 측정은 화면 표시 FPS가 아닌 처리량을 재므로 추천은 보수적으로 합니다.
- **검증:** `settings.cfg` 없는 첫 실행과 이후 실행에서 기존 설정이 유지되는지 확인하고, `benchmark_native.py`·`profile_web.py`로 프리셋을 비교합니다.
- **우선순위:** P2

### 7.2 선택형 업데이트 알림

- **내용:** 플레이어가 동의하면 GitHub Releases를 하루 최대 한 번 확인해 "X 버전이 나왔습니다"와 릴리스 페이지 열기 버튼을 보여 줍니다. 자동 다운로드나 교체는 하지 않습니다.
- **이유:** 메인 메뉴는 빌드 표시(`modern_version.bb`, `core/version.txt`)를 보여 주지만, 플레이어는 GitHub를 방문해야만 수정 사항을 알 수 있습니다. 웹 빌드는 항상 최신이므로 필요 없습니다.
- **위치:** Blitz `sockets` 모듈에는 TLS가 없으므로 플랫폼 서비스의 비동기 HTTPS(Windows는 WinHTTP, macOS는 `NSURLSession`)를 씁니다. 채널(안정판 또는 `dev`)은 `build-info.json` 빌드 정보에서 읽습니다.
- **에디션:** 공유, 데스크톱 빌드만.
- **공수 / 리스크:** M. 네트워크 실패는 조용히 넘기고 식별 정보는 보내지 않습니다.
- **검증:** 오프라인, 요청 제한, 더 새로운·같은·더 오래된 버전, 두 채널을 확인합니다.
- **우선순위:** P2, 1.2와 함께 진행
