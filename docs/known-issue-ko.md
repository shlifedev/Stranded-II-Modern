# 알려진 문제

[English](known-issue.md) · [한국어](known-issue-ko.md)

[개발 가이드](development-ko.md)

2026-10-15 기준 아래 문제는 미수정 상태입니다. Stranded II와 Extended가 공유하는 게임 코드에 있습니다. Stranded II의 macOS ARM64 / Metal 빌드에서 사용자 데이터와 분리된 게임 함수 테스트로 확인했으며, 수동 마우스 조작과 Windows·Extended 실행은 검증하지 않았습니다.

## 건설 미리보기: 배치와 취소 입력이 겹칠 때 종료

**상태:** 두 입력이 같은 프레임에 들어오면 크래시가 재현됩니다. 배치만 하거나 취소만 하는 경우는 통과했습니다.

**플레이어 재현 순서:** 망치를 장착하고 보조 동작(기본 우클릭)으로 건설 메뉴를 연 뒤 건물을 선택합니다. 게임 화면 위에서 왼쪽 마우스 버튼을 누른 채 미리보기를 회전하다가, 왼쪽 버튼을 놓는 순간 오른쪽 버튼을 눌러 취소합니다. 두 입력이 같은 프레임에 들어와야 하므로 수동 재현은 타이밍에 따라 달라집니다.

**원인:** [game_build.bb](../src/engine/includes/game_build.bb)의 `game_buildsetup_update()`가 왼쪽 버튼 놓기와 오른쪽 버튼 누르기를 독립적으로 처리합니다. 두 분기가 모두 `game_buildsetup_end()`를 호출하며, 이 함수는 `in_buildsetup_dummy`를 해제한 뒤 값을 비우지 않습니다. 두 번째 호출에서 같은 네이티브 핸들을 다시 해제합니다.

**검증 결과:** 유효한 미리보기 상태에서 `in_mrelease(1)=1`, `in_mhit(2)=1`을 함께 전달하면 같은 핸들이 두 번 해제되고 `Invalid or released native handle`과 함께 종료 코드 1로 끝났습니다. 각 입력을 따로 전달하면 정상 종료했습니다.

**수정 방향 — 미적용:** 한 번의 갱신에서 배치·취소를 한 번만 끝내고, 미리보기 해제 전 유효 여부를 검사하며 해제 후 핸들을 비웁니다. 일반 배치, 일반 취소, 두 입력이 겹치는 경우를 다시 검증합니다.

## 통나무배·돛뗏목: 완성 이벤트 누락과 잘못된 배열 접근

**상태:** 배열 범위 밖 접근과 완성 스크립트 누락을 확인했습니다. 테스트한 macOS 릴리스 빌드에서는 크래시가 **재현되지 않았습니다**.

**플레이어 재현 순서:** 일반 건설 과정으로 통나무배나 돛뗏목을 만들고 마지막 망치 동작으로 완성합니다. 이때 문제 경로에 도달하지만, 배는 정상적으로 나타날 수 있고 내부 이벤트 누락이 화면에 드러나지 않을 수 있습니다. 즉시 종료를 기대하기보다 `build_finish` 작업을 추적해 확인해야 합니다.

**원인:** 탈것 건설은 유닛 종류를 음수로 표시합니다. 통나무배는 `-31`, 돛뗏목은 `-30`입니다. [game_build.bb](../src/engine/includes/game_build.bb)의 `game_build()`에서 이벤트 키는 `Abs(typ)`으로 조회하지만, 스크립트는 `Dunit_script$(typ)`으로 조회합니다. 따라서 `dugoutbuild` 또는 `sailraftbuild`를 발생시킬 유닛 완성 스크립트 대신 배열 앞쪽의 메모리를 읽습니다.

**검증 결과:** 정상 스크립트 길이는 통나무배 87, 돛뗏목 421이지만, 실제 완성 작업에는 모두 길이 0의 빈 스크립트가 전달됐습니다. 두 실행 모두 정상 종료했습니다. 잘못된 메모리 접근에 따른 크래시 위험은 있으나, 이 결과로 릴리스 빌드에서 크래시가 재현됐다고 판단할 수는 없습니다.

**수정 방향 — 미적용:** 탈것 완성 시 `Dunit_script$(Abs(typ))`을 사용합니다. 두 배의 완성 이벤트를 검증하고 일반 건물의 완성 처리가 유지되는지도 확인합니다.
