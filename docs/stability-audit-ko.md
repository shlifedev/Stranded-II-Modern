# 안정성·성능 조사 — 2026-10-15

[English](stability-audit.md) · [한국어](stability-audit-ko.md)

[알려진 문제](known-issue-ko.md) · [개발 가이드](development-ko.md)

이 문서는 [`a65becb`](https://github.com/shlifedev/Stranded-II-Modern/commit/a65becb140e92dfd8c872e1bcda088a4132b4406)에서 수행한 조사 결과입니다. 기본 게임·Extended의 공유 코드, 컴파일러/런타임, 웹, Studio, 빌드·검증 도구, 리소스를 대상으로 위험 중심 소스 검토와 가능한 자동 검증을 수행했습니다. 모든 코드 줄이나 플레이 조합을 검증했다는 뜻은 아닙니다. 제품 결함 4건과 검증 도구·상태 결함 6건을 확인했으며, 조사에서는 제품 코드를 수정하지 않았습니다.

**후속 변경 구분:** 문서화 시점의 `01e0778`에는 `a09a0d6`의 Studio 변경이 포함돼 있습니다. T01·T02의 테스트 환경 수정이 소스에 반영됐고, 새 프로젝트의 v3 저장 구조와 세션 처리가 추가됐습니다. 아래 테스트 수와 성능 수치는 조사 기준 커밋의 결과이며, 현재 전체 테스트 결과나 v3 성능을 나타내지 않습니다. 이번 문서화에서는 게임 빌드·플레이 검사를 다시 실행하지 않았습니다. D03과 P01은 현재 저장 형식별 재검증이 필요합니다.

## 제품 결함

P1은 먼저 수정할 데이터 손실·프로세스 종료·잘못된 메모리 읽기 문제, P2는 다음 수정 대상입니다. 소스 링크는 탐색용이며 재현 결과는 위 기준 커밋에 해당합니다.

### D01 · P1 · 잘못된 맵 암호가 현재 장면을 삭제

- **재현:** 인게임 편집기에 지형과 오브젝트가 있는 상태에서 암호 보호 맵을 틀린 암호로 `load_map`에 전달합니다.
- **관측:** macOS 실제 게임 엔진에서 반환값은 `0`, 기존 오브젝트는 `1→0`, 지형 핸들은 `0`이 됐습니다.
- **원인:** [e_load_map.bb](../src/engine/includes/e_load_map.bb)의 `load_map`이 헤더·암호 검사 전에 `e_clear()`를 호출합니다. 암호 오류의 조기 반환에는 `CloseFile`도 없습니다. 파일 미해제는 소스로 확인했으며 OS 핸들 증가량은 측정하지 않았습니다.
- **개선·완료 조건:** 상태 변경 전에 입력을 검증하고, 로드 성공 후 장면을 교체하며 모든 종료 경로에서 파일을 닫습니다. 틀린 암호·잘린 파일·잘못된 헤더에서 현재 장면이 보존되고 정상 맵·저장 파일 왕복이 유지돼야 합니다.

### D02 · P1 · 짧은 문자열 읽기가 미초기화 영역을 포함

- **재현:** 길이 필드가 `64`이고 본문은 `1`바이트뿐인 파일에서 `ReadString`을 호출합니다.
- **관측:** macOS 실제 콘솔 런타임이 길이 `64`의 문자열을 반환했습니다. 나머지 메모리 내용 자체는 수집하지 않았습니다.
- **원인:** [stream.cpp](../src/blitz3d/src/modules/bb/stream/stream.cpp)의 `bbReadString`은 읽은 길이가 요청 길이와 같은지 검사하지 않고, 반환값이 0이 아니면 `std::string(buff,len)`을 만듭니다. 길이 기반 할당에도 상한이 없습니다.
- **영향:** 손상 파일의 비결정적 문자열과 과대 할당 위험이 있습니다. 미초기화 메모리를 포함하는 경로는 확인했지만 악용이나 외부 유출을 실증한 것은 아닙니다.
- **개선·완료 조건:** 정확한 읽기 길이와 EOF 처리를 정의하고 포맷 파서에서 남은 크기·허용 길이를 검증합니다. 부분 본문·음수·과대 길이는 통제된 실패로 처리하고 정상 문자열·32비트 바이너리 ABI를 유지합니다.

### D03 · P1 · NaN 좌표 맵 조회가 Studio 서버를 종료

- **재현:** 새 맵의 시작점 `x`를 NaN으로 바꾼 뒤 JSON 서버에 `map.import → inspect → schema`를 전달합니다.
- **관측:** 가져오기와 검증이 성공해 revision `1`로 저장됐습니다. `inspect`의 JSON 직렬화가 `ValueError`로 서버를 종료했고 후속 `schema` 응답이 없었습니다.
- **원인:** [maps.py](../scripts/studio_core/maps.py)와 [project.py](../scripts/studio_core/project.py)가 가져온 좌표의 유한성을 검증하지 않고, [studio.py](../scripts/studio.py)의 `allow_nan=False` 직렬화가 요청 예외 처리 밖에 있습니다. 편집 연산의 숫자 검증만으로 가져오기 경로를 보호할 수 없습니다.
- **개선·완료 조건:** 가져온 좌표·회전·크기·지형 수치의 NaN/±Infinity를 커밋 전에 거부하고 직렬화 오류를 요청 단위 오류로 반환합니다. 프로젝트가 변경되지 않고 다음 정상 요청에 응답해야 합니다. 후속 Studio 변경을 포함해 v1/v2/v3별 재현 여부를 다시 확인해야 합니다.

### D04 · P2 · 손상된 임시 저장 파일이 Studio 시작을 차단

- **재현:** 분리한 `userData`에 잘린 `authoring-drafts.json`을 두고 실제 [main.cjs](../studio/electron/main.cjs)의 초기화 코드를 실행했습니다. Electron API만 VM 대역으로 바꿨습니다.
- **관측:** `JSON.parse` 오류가 `app.quit`으로 이어져 창 생성에 도달하지 못했습니다. 이 오류 조건에서 실제 Electron 전체 시작을 검증한 것은 아닙니다.
- **개선·완료 조건:** 손상 파일을 보존·격리하고 임시 저장 없이 시작할 수 있도록 복구 안내를 제공합니다. 잘린 JSON·잘못된 최상위 타입·읽기 실패를 처리하면서 정상 임시 저장의 세션 간 보존을 유지합니다.

## 성능

### P01 · Studio 편집 이력 재실행 비용 — 실측

기준 커밋의 v1 프로젝트에서 32×32 맵에 `strength=0` 브러시 명령을 누적했습니다. 최종 맵은 항상 91,163바이트였습니다. `snapshot` 3회 중앙값은 다음과 같습니다.

| 누적 명령 | 0 | 50 | 200 | 500 | 1,000 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 조회 시간(ms) | 13.64 | 16.73 | 25.76 | 44.75 | 75.76 |

[project.py](../scripts/studio_core/project.py)의 `map_bytes`가 모든 `edits`를 매번 파싱·재실행합니다. 동일 장면에서 약 5.56배로 증가했지만 순차 실행과 OS 캐시 영향을 포함하며 전체 UI 지연 측정은 아닙니다. revision별 결과 캐시, 무효 연산 제거, 체크포인트가 개선 후보입니다. undo/redo와 원본 바이너리 보존을 함께 검증해야 합니다. **후속 v3의 현재 상태 저장 구조에는 이 수치를 그대로 적용할 수 없습니다.**

### P02 · Metal 렌더링 기준값 — 실측, 병목 후보

실제 macOS ARM64/Metal 렌더링에서 2048×1152, FPS 제한 해제, 3초 준비 후 8초 측정했습니다. 각 조건에 새 프로세스를 사용했습니다. water/lighting/atmosphere ON, shadows OFF, FXAA, water=6·grass=4·view=4, AI/애니메이션 OFF입니다. 감사용 엔진 복사본의 내장 벤치마크를 실제 시간으로 자동 구동했으며 대화형 플레이 FPS는 아닙니다.

조건별 3회와 재시도 1회, 총 13회 중 포커스 손실 3회를 제외한 유효 결과입니다. 모든 열은 trial별 값의 중앙값이며 p95는 합친 프레임의 p95가 아닙니다.

| 추가 오브젝트 | 유효 횟수 | FPS [최소–최대] | 평균 프레임(ms) | p95(ms) | peak RSS(MiB) |
| ---: | ---: | ---: | ---: | ---: | ---: |
| 0 | 3 | 179.53 [119.96–224.98] | 5.56 | 9.09 | 285.3 |
| 256 | 3 | 156.84 [149.56–208.31] | 6.37 | 11.88 | 294.2 |
| 768 | 2 | 149.06 [136.51–161.60] | 6.75 | 13.17 | 301.8 |
| 1,536 | 2 | 129.66 [121.35–137.98] | 7.74 | 14.09 | 316.2 |

0→1,536개에서 CPU self 시간은 main 0.45→2.34ms, reflection 0.35→1.29ms, physics 0.54→1.00ms였습니다. flip 구간도 2.89–4.35ms여서 총 FPS만으로 원인을 단정하지 않습니다. 메인·반사 장면 준비와 드로우 수집을 더 측정하되 반사 주기·잔디·거리·그래픽 품질을 낮추지 않습니다. GPU pass 시간은 업로드와 pass 사이 공백을 모두 포함하지 않으며 CPU 시간과 겹칠 수 있습니다. p99/raw frame은 미수집, peak RSS는 장시간 누수 증거가 아닙니다.

### 미실측 후보

- **P03:** [QOL 인벤토리](../src/engine/includes/qol_inventory.bb)가 행을 재생성하고 삽입 정렬합니다. 큰 인벤토리에서 변경 시에만 재계산하는 캐시를 측정할 가치가 있으나 병목은 확정하지 않았습니다. 양 에디션 기본값과 저장된 설정을 유지해야 합니다.
